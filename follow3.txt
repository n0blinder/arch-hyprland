=========================================================
Arch Linux Hyprland Automated Installation Plan (v3)
=========================================================

Purpose:
Take a clean Arch install that already has EVERYTHING EXCEPT the GUI
(locale, partitions, swap, timezone, users, passwords, NetworkManager
are done via archinstall) and bring it up to a fully configured,
ready-to-go Hyprland desktop: all packages, GPU drivers (AMD + NVIDIA),
services, dotfiles, and app configs.

Target hardware:
ThinkPad P16v Gen1 - AMD CPU, AMD Radeon iGPU + RTX (NVIDIA) dGPU (hybrid).

NOTE ON THE ARCHINSTALL BASELINE
--------------------------------
The clean install is done WITHOUT the archinstall "hyprland" profile
and WITHOUT the video-driver profiles. Therefore this guide installs
EVERYTHING itself and does NOT assume any of the following are already
present: hyprland, kitty, dolphin, dunst, grim, slurp, wofi,
xdg-desktop-portal-hyprland, polkit-kde-agent, qt5/qt6-wayland,
mesa, vulkan-radeon, xf86-video-*, nvidia-*, etc.
(If you DO use the archinstall hyprland/GPU profiles, some packages
below will already be installed - pacman/yay will simply skip them.)

=========================================================
PRE-FLIGHT NOTES (read before scripting)
=========================================================

1. Run as your normal (sudo-capable) user, NOT as root. The script uses
   sudo where needed and installs user services under your account.

2. Username: several shipped configs contain a hardcoded "/home/tony"
   path (e.g. .config/ashell/config.toml). On deploy, replace "tony"
   with the actual $USER, or prefer $HOME-relative paths.

3. The Hyprland config uses the NEW Lua config format (hl.* API,
   require("monitors") etc.). This requires a recent Hyprland build with
   Lua-config support. Verify the entry-point file name Hyprland expects
   for your version before relying on it.

4. Do NOT deploy the leftover files: hyprland-default.bak, and the stray
   .config/hypr/.bashrc / .config/hypr/.zshrc.

SECTION 12 - GPU drivers: AMD  (Radeon 780M / RDNA3, PRIMARY GPU)
=========================================================

The AMD iGPU is the DEFAULT/primary GPU. Everything runs on it; the
NVIDIA dGPU stays asleep unless explicitly used (see Section 14).

The kernel amdgpu driver (in-kernel) + Mesa do all the work on Wayland.
NOTE: NO Xorg DDX packages. xf86-video-ati is for pre-2013 radeon cards
(wrong hardware) and xf86-video-amdgpu is unused under Wayland - BOTH
are intentionally omitted.

    mesa
    vulkan-radeon         # RADV Vulkan driver
    vulkan-tools          # provides vulkaninfo
    libva-mesa-driver     # VA-API hardware video decode on the iGPU
    mesa-vdpau            # VDPAU hardware video decode on the iGPU

Command:

    sudo pacman -S --needed --noconfirm \
        mesa vulkan-radeon vulkan-tools libva-mesa-driver mesa-vdpau

(amdgpu firmware ships in linux-firmware, already present from the base
install. No [multilib]/lib32 packages - 32-bit GPU accel is not needed.)

Verify:

    vulkaninfo --summary


=========================================================
SECTION 13 - GPU drivers: NVIDIA (RTX A500 / GA107 Ampere, dGPU)
=========================================================

Decision: OPEN kernel modules (nvidia-open supports Turing+; Ampere is
supported). The dGPU is SECONDARY - installed and modeset-enabled for
on-demand offload, but kept powered off when idle (Section 14).

    nvidia-open-dkms
    nvidia-utils
    nvidia-prime          # provides prime-run for on-demand dGPU offload
    egl-wayland
    linux-headers         # required to build the dkms module
    dkms                  # (dependency; install explicitly to be safe)

Command:

    sudo pacman -S --needed --noconfirm \
        nvidia-open-dkms nvidia-utils nvidia-prime egl-wayland \
        linux-headers dkms

(No lib32-nvidia-utils / no libva-nvidia-driver: 32-bit accel is not
needed, and video decode is done on the AMD iGPU, not NVIDIA. This means
[multilib] does NOT need to be enabled - one less configuration step.)

Module options - create /etc/modprobe.d/nvidia.conf with:

    options nvidia_drm modeset=1 fbdev=1
    options nvidia NVreg_DynamicPowerManagement=0x02

    -> modeset=1 : required for Wayland/Hyprland.
    -> NVreg_DynamicPowerManagement=0x02 : RTD3 fine-grained runtime
       power management, lets the idle dGPU (and its VRAM) power OFF.

Early-load the modules so KMS is available at boot. Edit
/etc/mkinitcpio.conf and set:

    MODULES=(nvidia nvidia_modeset nvidia_uvm nvidia_drm)

Regenerate the initramfs (also pulls in the new modprobe.d file):

    sudo mkinitcpio -P

Reboot:

    sudo reboot

Verify after reboot:

    cat /sys/module/nvidia_drm/parameters/modeset      # expect: Y
    nvidia-smi
    lsmod | grep nvidia


=========================================================
SECTION 14 - Hybrid GPU: AMD-primary + dGPU power-off + verify
=========================================================

GOAL: Hyprland renders on the AMD iGPU by default; the NVIDIA dGPU stays
suspended until you explicitly offload work to it.

(1) Make the AMD iGPU the PRIMARY render device.
    Hyprland's aquamarine backend reads AQ_DRM_DEVICES; the FIRST device
    listed is primary. We point it at the amdgpu card node first.

    The correct node is machine-specific - the install script auto-
    detects which /dev/dri/cardN is bound to amdgpu. Manual check:

        for c in /sys/class/drm/card[0-9]; do
            printf '%s -> ' "$c"
            basename "$(readlink -f "$c/device/driver")"
        done
        # note which cardN shows "amdgpu"

    Set it in the uwsm session environment so it is exported BEFORE the
    compositor starts:

        mkdir -p ~/.config/uwsm
        # example if amdgpu is card1 and nvidia is card0:
        echo 'export AQ_DRM_DEVICES=/dev/dri/card1:/dev/dri/card0' \
            >> ~/.config/uwsm/env

    (The install script writes this line using the auto-detected node.
    Using the wrong node can cause a black screen at login, so the
    script verifies the amdgpu node exists before writing it.)

(2) dGPU power-off is otherwise automatic.
    nvidia-utils ships udev rules that enable RTD3 runtime PM for Turing+
    GPUs; combined with NVreg_DynamicPowerManagement=0x02 (Section 13)
    the idle dGPU suspends on its own. No service needed.
    (nvidia-powerd.service = Dynamic Boost for PERFORMANCE, not battery -
    intentionally NOT enabled.)

(3) On-demand dGPU use:
        prime-run <application>
    or:
        __NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia <app>

Verification:

    lspci -k | grep -EA3 'VGA|3D|Display'     # both amdgpu + nvidia
    lsmod | grep amdgpu                          # amdgpu loaded
    lsmod | grep nvidia                          # nvidia loaded
    glxinfo -B | grep "OpenGL renderer"          # should say AMD/Radeon
    hyprctl systeminfo | grep -i gpu             # AMD is the active GPU

    # dGPU should read "suspended" when idle (replace with your PCI addr,
    # find it via: lspci | grep -i nvidia):
    cat /sys/bus/pci/devices/0000:XX:00.0/power/runtime_status

    # confirm offload routes to NVIDIA on demand:
    prime-run glxinfo -B | grep "OpenGL renderer"   # should say NVIDIA

CPU vs GPU battery note: auto-cpufreq (Section 10) manages the CPU only
(governor + turbo, AC-aware). The dGPU power-off is handled by the
NVIDIA config above. Together they cover battery on the CPU and dGPU;
the AMD iGPU scales with the APU power budget automatically (faster when
plugged in).

External displays: on the P16v, external HDMI/USB-C outputs may be wired
through the NVIDIA dGPU, so connecting an external monitor can wake it.
This is expected hardware behaviour, not a misconfiguration.

=========================================================
SECTION 17 - Session launcher script  (/usr/local/bin) + uwsm
=========================================================

greetd's config.toml launches a command that MUST exist in PATH.
We standardize on the name "start-hyprland-session" and launch Hyprland
THROUGH uwsm so it runs as a managed systemd session.

Background on uwsm launch mechanics:
    Hyprland ships two session files in /usr/share/wayland-sessions/:
        hyprland.desktop        -> Exec=Hyprland        (plain compositor)
        hyprland-uwsm.desktop   -> Exec=uwsm start ...   (uwsm wrapper)
    To start via uwsm we run "uwsm start hyprland.desktop" (the PLAIN
    session file). Do NOT feed hyprland-uwsm.desktop to "uwsm start" or
    you would wrap uwsm inside uwsm.

Install the launcher (uwsm version):

    sudo cp start-hyprland-session /usr/local/bin/start-hyprland-session
    sudo chmod +x /usr/local/bin/start-hyprland-session

Required contents of the launcher (UPDATE the shipped file to this):

    #!/bin/sh
    # Launch Hyprland as a managed uwsm session.
    if uwsm check may-start; then
        exec uwsm start hyprland.desktop
    fi

(The old contents were "exec Hyprland" - replace them. The
"uwsm check may-start" guard prevents starting a second session if one
is already running.)

VERIFY the available session id on the target machine:

    uwsm check                      # sanity check
    ls /usr/share/wayland-sessions/ # confirm hyprland.desktop exists

IMPORTANT NAME RECONCILIATION:
The shipped greetd/config.toml active line currently calls
"--cmd start-hyprland". Update it to point at this launcher's full path:
    --cmd /usr/local/bin/start-hyprland-session
so greetd (Section 18) and this script agree on the name.

NOTE: with uwsm managing the session, the
"dbus-update-activation-environment" line in autostart.lua is redundant
(uwsm imports the environment into systemd/D-Bus itself). It is harmless
to leave in place. Persistent env vars can also be set in
~/.config/uwsm/env if you prefer them over environment.lua.

1. Wallpaper image must be added to repo (wallpapers/) - user-supplied.
2. Confirm the Hyprland Lua-config entry point for the installed Hyprland
   version (hyprland.lua vs hyprland.conf) - the config uses the new
   Lua API. Test on target before trusting unattended.
3. [multilib] is NOT required (no lib32 packages). Leave it disabled.
   AQ_DRM_DEVICES: the install script must auto-detect the amdgpu card
   node and verify it exists before writing ~/.config/uwsm/env - a wrong
   node can black-screen the login. Confirm on the target with the
   /sys/class/drm loop in Section 14.
4. Username templating: verify no other shipped config hardcodes "tony".
5. brave-bin / mullvad-vpn-bin vs source builds - pick per preference.
6. uwsm: confirm "uwsm check" passes and that
   /usr/share/wayland-sessions/hyprland.desktop exists on the target, so
   "uwsm start hyprland.desktop" resolves (Section 17). The shipped
   start-hyprland-session file (currently "exec Hyprland") must be
   updated to the uwsm launcher, and greetd/config.toml's --cmd updated
   to /usr/local/bin/start-hyprland-session - the install script will
   handle both.
